Built and verified on the working branch, held back from main for one reason: the Worker now binds an R2 bucket, and a deploy fails if the bucket does not exist yet. Make it, tell me, and I release.

**Your step, once.** In the Cloudflare dashboard open R2 Object Storage and create a bucket named exactly `wwws-data`. Cloudflare may ask for a card on file to switch R2 on; the free allowance covers this. Nothing else is needed: no password, no key, no sign-in, as you asked.

**What the release does.** The site reads the bucket on its own address, open to anyone, and shows a company from the first of these: a copy you fetched, the store, a bundled sample, the fetch form. The home page says what the store holds by exchange. Watchlists mark the companies that are in it. A new Screen tab lists every company of an exchange with the latest year's figures and the book's ratios, sortable by any column, searchable by name or ticker, with the book's rules of thumb as tick-boxes and a count of how many each company meets. Companies with no statements at EODHD are counted and left out. Until the bucket has something in it, the site reads exactly as it does today.

**Filling the store.** The local pull page has a second form, Send to the site. It wants an R2 API token: in the dashboard open R2, then Manage R2 API Tokens, create a token with Object Read & Write on the bucket, and copy the endpoint, the Access Key ID and the Secret Access Key it shows into the form. Tick remember and press Send. It uploads the companies with statements, the screen rows and an index straight from your data folder to your bucket, and next time skips whatever is unchanged. The raw replies, the rows and the CSVs stay on your machine. The same runs from the command line with `npm run upload-store`. The keys stay on your machine, like the EODHD token.

**Verified.** Dry-run deploy clean with the binding. The real Worker served a seeded local bucket: the index, a company file, screen rows, a 304 for a browser that has the file already, 404s for anything else, refusals for other methods. The uploader ran against a mock of R2's S3 interface that recomputes every signature, and the signer matches AWS's own published test vector. The pull page sent a pull to that mock from a browser, with wrong keys refused plainly. The page's store behaviour and the whole Screen were driven in a headless browser against your real NASDAQ and NYSE rows, on desktop and phone, and the earlier suites still pass.
